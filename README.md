# Лаборатори №7 — Exploratory Testing (SBTM)

**Сэдэв:** Exploratory тест — SBTM session, charter, алдааны тайлан  
**Оюутан:** Оюунсүрэн Мөнхзолбоо  
**Оюутны код:** B210910878  
**Огноо:** 2026-10-19

## 1. Зорилго

Энэхүү лабораторийн ажлын зорилго нь номын бүртгэлийн веб аппликейшнд Exploratory Testing аргачлалаар шинжилгээ хийж, Session-Based Test Management (SBTM) ашиглан туршилтын явц, ажиглалт, илэрсэн алдааг баримтжуулах явдал юм.

Туршилтыг эх кодыг урьдчилан судлахгүйгээр, хэрэглэгч болон API-ийн түвшинд гүйцэтгэсэн.

## 2. Ашигласан орчин

- **Үйлдлийн систем:** Windows
- **Node.js:** v24.19.0
- **Хөтөч:** Google Chrome
- **Туршилтын хэрэгсэл:** PowerShell, curl, VS Code
- **Аппликейшн:** Багшаас өгсөн `app.js`

## 3. Аппликейшнийг ажиллуулах

Төслийн үндсэн хавтсанд терминал нээж дараах командыг ажиллуулна.

```powershell
node app.js
```

Дараа нь веб хөтчөөр дараах хаягт хандана.

```text
http://localhost:3000
```

Аппликейшнийг дахин эхлүүлэхэд санах ойд хадгалагдсан номын өгөгдөл анхны төлөвтөө шилжинэ.

## 4. Туршилтын аргачлал

Туршилтад SBTM аргачлалыг ашиглаж, 60 минутын хугацаатай нэг session гүйцэтгэсэн.

Туршилтын явцад ном нэмэх, хайх, устгах, өгөгдөл шалгах, хэрэглэгчийн интерфейс болон API-ийн алдааны боловсруулалтыг судалсан.

Туршилтын зорилго, хамрах хүрээ болон сонгосон tour-уудыг session эхлэхээс өмнө charter баримтад тодорхойлсон.

**Баримт бичгүүд:**

- [Session charter](charter.md)
- [Session report](session-report.md)
- [Туршилтын анхны тэмдэглэл](observations.txt)

## 6. SBTM session-ийн үр дүн

**Нийт хугацаа:** 60 минут

| Үйл ажиллагаа | Хугацааны хувь |
|---|---:|
| Орчин бэлтгэх | 5% |
| Туршилт гүйцэтгэх | 65% |
| Алдаа судлах, дахин шалгах | 30% |
| **Нийт** | **100%** |

Дэлгэрэнгүй үр дүнг [session-report.md](session-report.md) файлаас үзнэ үү.

## 7. Дүгнэлт (Debrief)

Энэ лабораторийн ажлаар Exploratory Testing аргачлалыг бодит веб аппликейшнд хэрэгжүүлж туршлаа. SBTM ашигласнаар туршилтын зорилго болон хугацааг тодорхой болгож чадсан. Туршилтын явцад төлөвлөсөн шалгалтаас гадна шинэ нөхцөлүүдийг шууд туршиж үзэх боломжтой байв. Номын нийт тоо хүснэгтийн бодит мөрийн тоотой зөрж байгааг илрүүлсэн. Мөн устгах товчны өнгө шаардлагад нийцэхгүй байгааг ажигласан. API-д буруу бүтэцтэй JSON илгээхэд HTTP 400 биш, 200 хариу ирсэн нь алдааны боловсруулалт хангалтгүй байгааг харуулсан. Алдаа бүрийг дахин давтах алхам, хүлээгдэж буй болон бодит үр дүн, нотлох баримтаар баримтжуулсан. Анхны тэмдэглэл болон screenshot-уудыг хадгалснаар туршилтын явцыг эргэн шалгах боломж бүрдсэн. Энэхүү ажлаар exploratory тестийг зөвхөн алдаа хайх бус, системийн үйл ажиллагааг судалж ойлгох арга гэдгийг мэдэж авсан.
