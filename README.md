**Сэдэв:** Exploratory тест — SBTM session, charter, алдааны тайлан

## 1. Зорилго

Энэхүү лабораторийн ажлын зорилго нь номын бүртгэлийн веб аппликейшнд Exploratory Testing аргачлалаар шинжилгээ хийж, Session-Based Test Management (SBTM) ашиглан туршилтын явц, ажиглалт, илэрсэн алдааг баримтжуулах явдал юм.

Туршилтыг эх кодыг урьдчилан судлахгүйгээр, хэрэглэгч болон API-ийн түвшинд гүйцэтгэсэн.

## 2. Ашигласан орчин

- **Үйлдлийн систем:** Windows
- **Node.js:** v24.19.0
- **Хөтөч:** Google Chrome
- **Туршилтын хэрэгсэл:** PowerShell, curl, VS Code
- **Аппликейшн:** Багшаас өгсөн `app.js`

## 3. Аппликейшнийг ажиллуулах

Төслийн үндсэн хавтсанд терминал нээж дараах командыг ажиллуулна.

```powershell
node app.js
```

Дараа нь веб хөтчөөр дараах хаягт хандана.

```text
http://localhost:3000
```

Аппликейшнийг дахин эхлүүлэхэд санах ойд хадгалагдсан номын өгөгдөл анхны төлөвтөө шилжинэ.

## 4. Туршилтын аргачлал

Туршилтад SBTM аргачлалыг ашиглаж, 60 минутын хугацаатай нэг session гүйцэтгэсэн.

Туршилтын явцад ном нэмэх, хайх, устгах, өгөгдөл шалгах, хэрэглэгчийн интерфейс болон API-ийн алдааны боловсруулалтыг судалсан.

Туршилтын зорилго, хамрах хүрээ болон сонгосон tour-уудыг session эхлэхээс өмнө charter баримтад тодорхойлсон.

## 7. Дүгнэлт (Debrief)

Энэ лабораторийн ажлаар Exploratory Testing аргачлалыг ашиглан номын бүртгэлийн веб аппликейшнийг 60 минутын хугацаанд туршиж үзлээ. SBTM ашигласнаар туршилтын зорилго, хугацаа болон ажиглалтуудаа нэг дор тэмдэглэх боломжтой болсон. Couch Potato Tour-ийн үед номын гарчиг, зохиолч, оныг хоосон үлдээгээд нэмэхэд алдаа заалгүй хоосон ном бүртгэгдэж байгааг илрүүлсэн. Saboteur Tour-ийн үед API-д буруу JSON илгээхэд HTTP 400 Bad Request биш, 200 OK буцааж байгааг олсон. Мөн API-д зөвхөн title талбартай хүсэлт илгээхэд бусад мэдээлэл дутуу байсан ч ном нэмэгдэж байв. Charter-аас гадуур номын нийт тоо зөрөх, устгах товч ногоон байх, хайлт том жижиг үсгээс хамаарах зэрэг алдаануудыг ажигласан. Харин ачааллын тест болон олон хэрэглэгч зэрэг ажиллах нөхцөлийг энэ session-д шалгаагүй. Playwright ашигласан автомат тест нь давтагддаг үйлдэл болон хүлээгдэж буй үр дүнг шалгахад илүү тохиромжтой гэж үзсэн. Харин хүний нүдээр шалгахад товчны өнгө, хүснэгтийн харагдах байдал болон ойлгомжгүй талбаруудыг анзаарахад илүү хялбар байсан. Энэ ажлаар exploratory тест хийх үед төлөвлөсөн шалгалтаас гадна шинэ алдаа олж, тэдгээрийг анхны тэмдэглэл болон screenshot-оор баримтжуулахын ач холбогдлыг ойлгосон.
